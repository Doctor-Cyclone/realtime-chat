# Проверка реализации

Автоматизированные проверки повторно выполнены 12 октября 2026 года; ручные проверки в браузере выполнены 9 октября 2026 года на Windows, Node.js 24.11.1 и pnpm 11.25.0.

## Автоматизированные проверки

- `pnpm typecheck`: строгая типизация всех пакетов и тестовых файлов.
- `pnpm test`: 21 тест в пяти файлах после рефакторинга.
- `pnpm build`: production-сборка shared, backend и frontend.
- `pnpm format:check`: единое оформление исходников и документации.

| Набор            | Проверяет                                                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Shared, 2 теста  | Контракт, направление событий, UUID, nickname и длину текста                                                                               |
| Client, 9 тестов | Регистрацию, backoff/cap/reset, timeout входа, ACK, retry, дубли событий, malformed data, cleanup и typing                                 |
| UI, 2 теста      | Вход, отправку по Enter и кнопке, Shift+Enter, typing, выход, retry, уведомления и отсутствие дубликатов                                   |
| Hook, 1 тест     | Настоящий React Strict Mode setup/cleanup, подписку состояния и отмену reconnect при unmount                                               |
| Server, 7 тестов | Реальную сеть: broadcast, историю, пользователей, dedup через reconnect, валидацию, maxPayload, typing/refresh и восстановление ChatClient |

Серверные тесты используют свободные локальные порты и закрывают сервер после каждого теста. Тесты таймеров требуют нулевого количества оставшихся таймеров после disconnect.

## Проверки в браузере

После рефакторинга добавлены два jsdom-теста взаимодействия UI-компонентов: вход, отправка по Enter и кнопке, Shift+Enter, typing, выход, отображение сообщения с потерянным ACK без дубликата, retry и закрытие уведомления. Проверки типов, существующие сетевые тесты и production-сборка повторно пройдены.

Frontend и backend запускались через `pnpm dev`. В двух отдельных вкладках:

1. Аня вошла в чат и отправила сообщение по Enter.
2. Интерфейс показал ACK: «Принято сервером».
3. Борис вошёл позже и получил историю.
4. В обеих вкладках список показал двух участников.
5. При вводе Бориса у Ани появился typing indicator.
6. Борис отправил ответ кнопкой; Аня получила его в реальном времени.
7. Desktop-верстка проверена визуально.

Мобильные CSS breakpoint реализованы. Изменение viewport в доступном встроенном браузере не применилось, поэтому визуальная проверка на мобильной ширине остаётся ручным сценарием; desktop-проверка и сетевые тесты выполнены.

## Как повторить вручную

1. Запустите `pnpm dev`, откройте две вкладки `http://127.0.0.1:5173/`.
2. Войдите с разными, затем с одинаковыми nickname. Участники должны оставаться отдельными.
3. Отправьте сообщение Enter и кнопкой. Проверьте историю в третьей вкладке.
4. Печатайте непрерывно больше 4 секунд: индикатор должен сохраняться; прекратите ввод — он исчезнет.
5. Для контролируемого сбоя запустите backend и frontend отдельно: `pnpm --filter @chat/shared build`, затем в разных терминалах `pnpm --filter @chat/server dev` и `pnpm --filter @chat/client dev`.
6. Остановите backend, оставив frontend. Ожидается Reconnecting и запрещённая отправка; запустите backend снова — Connected и новый список пользователей. История нового процесса пуста.
7. Нажмите «Выйти» во время reconnect: новых попыток быть не должно.
8. Измените ширину браузера на 390px: список участников открывается отдельной кнопкой, поле ввода и отправка помещаются на экране.
9. ACK timeout и retry удобно проверять автоматическими тестами: обычный сервер подтверждает сообщения сразу.

## Ограничения проверки

GitHub Actions запускает форматирование, проверку типов, тесты и сборку при push и pull request. Результаты каждого запуска доступны во вкладке Actions репозитория. Нет нагрузочных проверок, публичного размещения, авторизации и persistence. Полный список продуктовых ограничений — в README.
