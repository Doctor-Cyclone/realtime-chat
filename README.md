# Real-time Chat

Учебный многопользовательский чат на React, TypeScript и Node.js с обменом сообщениями через настоящий WebSocket.

## Текущий этап — интерфейс чата

В первой публикации подготовлены:

- pnpm monorepo: `apps/client`, `apps/server`, `packages/shared`;
- строгие настройки TypeScript и ESM;
- зависимости будущих frontend и backend;
- общие типы пользователей, сообщений и статусов соединения/доставки;
- отдельные discriminated unions для клиентских и серверных событий;
- runtime-валидаторы входящих событий и общие ограничения протокола;
- настройки форматирования и MIT-лицензия.

Во второй публикации добавлен WebSocket-сервер: вход пользователей, список участников, история сообщений, рассылка, ACK, защита от дублей, индикатор набора текста и heartbeat. Логика разделена на обработчики, сервисы, транспорт и хранилище. В третьей публикации добавлена клиентская логика: подключение, переподключение с увеличением задержки, отправка сообщений, ожидание ACK и повторная отправка, индикатор набора текста и подписка React на состояние через `useChat`. В четвёртой публикации добавлены экран входа, комната чата, список участников, сообщения со статусами доставки, повторная отправка, индикатор набора, уведомления об ошибках и адаптивные стили. Интерфейс разделён на компоненты.

## Стек

React · TypeScript · Vite · Node.js · ws · CSS Modules · pnpm. Автоматизированные тесты на Vitest будут добавлены отдельным этапом.

## Проверка текущего этапа

Требуется Node.js 22.13+ (рекомендуется Node.js 24 LTS) и pnpm 11.25.0.

```sh
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm typecheck
pnpm build
pnpm format:check
```

Сборка создаёт `packages/shared/dist`, `apps/server/dist` и `apps/client/dist`. Сгенерированные файлы не хранятся в Git.

## Запуск проекта

Для разработки: `pnpm dev`. Команда запускает сервер и интерфейс. Откройте http://127.0.0.1:5173, введите имя и присоединитесь к чату. Для проверки переписки откройте вторую вкладку.

После сборки `pnpm start` запускает сервер. Для просмотра собранного интерфейса задайте `VITE_WS_URL=ws://127.0.0.1:3001/ws` перед `pnpm build`, затем в отдельном терминале запустите `pnpm preview`. Этот адрес предназначен для локальной проверки.

По умолчанию сервер доступен на `ws://127.0.0.1:3001/ws`, проверка состояния — `http://127.0.0.1:3001/health`. Адрес и порт задаются переменными `HOST` и `PORT`.

История хранится в памяти и очищается после перезапуска. Авторизация и постоянное хранилище пока отсутствуют.

## Общий протокол

Все события содержат `type` и `payload`. Направления разделены на `ClientEvent` и `ServerEvent`.

| Направление     | События                                                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------ |
| Клиент → сервер | `user:join`, `message:send`, `typing:start`, `typing:stop`                                                         |
| Сервер → клиент | `user:join`, `users:list`, `message:history`, `message:new`, `message:ack`, `typing:start`, `typing:stop`, `error` |

TypeScript проверяет код при разработке, но не сетевые данные. Поэтому `isClientEvent` и `isServerEvent` принимают `unknown` и проверяют структуру, UUID и ограничения перед использованием события.

В контракте предусмотрены nickname до 24 символов, сообщения до 500 символов, история до 1000 записей и окно дедупликации до 5000 сообщений. Сервер проверяет входящие события перед обработкой и ограничивает размер WebSocket-кадра.

## Клиентская логика

`ChatClient` управляет соединением и хранит состояние чата. `DeliveryTracker` отслеживает таймауты подтверждения доставки. `useChat(nickname, url)` подключает клиент к React и закрывает соединение при размонтировании. `getWebSocketUrl` выбирает адрес из `VITE_WS_URL` либо формирует его из адреса страницы.

Клиент проверяет серверные события перед обработкой. Повторная отправка использует тот же идентификатор сообщения, чтобы сервер мог предотвратить дубли. ACK означает принятие сообщения сервером.

`pnpm typecheck` проверяет сервер и интерфейс; `pnpm dev` запускает оба приложения. Vite перенаправляет WebSocket-запросы `/ws` на локальный сервер.
